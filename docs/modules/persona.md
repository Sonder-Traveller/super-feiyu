# persona 模块设计

> 职责：拼装提示词。**不碰网络，不碰存储。**
> 核心使命：在保证人设鲜活的前提下，最大化前缀缓存命中率。

---

## 1. 为什么这道题重要

DeepSeek 定价（元 / 百万 token）：

| | 缓存命中 | 缓存未命中 |
|---|---|---|
| 输入 | 0.02 | 1 |
| 输出 | 4 | 4 |

**输入成本差 50 倍。**

人格 prompt 通常 3000–5000 token。若每轮都未命中：
- 100 轮/天 × 5000 token × 1 元/百万 = **0.5 元/天**
- 若命中：**0.01 元/天**

按月算：**15 元 vs 0.3 元**。这不是优化，是数量级差异。

**真正的风险**：把时间戳、"今天心情"、随机数拼进 system，
每轮都变，缓存永远不命中，而作者往往毫无察觉。

## 2. 分层结构

```
┌─────────────────────────────────────────┐
│ L1 稳定前缀（system）                     │  ← 逐字节恒定
│   ├─ 行为红线（rules.md）                 │
│   └─ 人格正文（persona.md）               │
├─────────────────────────────────────────┤
│ L2 历史（messages[]）                     │  ← 只追加
│   ├─ user: ...                           │
│   ├─ assistant: ...                      │
│   └─ user: ...                           │
├─────────────────────────────────────────┤
│ L3 动态尾部（最后一条 user）               │  ← 每轮变化
│   ├─ 当前时间（粗粒度）                    │
│   ├─ 场景（群聊/私聊/对方昵称）            │
│   ├─ 召回的相关记忆                        │
│   └─ 本轮微约束                            │
└─────────────────────────────────────────┘
```

**缓存边界在 L1 结束处**。L1 越稳定、越长，省的越多。

## 3. 接口设计

```cpp
class IPersona {
 public:
  // 稳定前缀：构造时拼好，之后只读返回
  [[nodiscard]] virtual std::string stable_prefix() const = 0;

  // 动态尾部：每轮生成
  [[nodiscard]] virtual std::string dynamic_suffix(
      const InboundMessage& msg,
      const std::string& recalled_memory) const = 0;
};
```

### 3.1 为什么 `stable_prefix()` 返回 `const std::string`

强制语义：**它不是一个可以随手拼东西的地方**。
返回 `const` 让调用方无法在返回值上追加动态内容——
想加动态内容只能走 `dynamic_suffix`。

### 3.2 `dynamic_suffix` 的入参

| 参数 | 用途 |
|---|---|
| `msg` | 拿时间、场景、对方昵称 |
| `recalled_memory` | 已由 store 召回并格式化的文本 |

**注意**：`recalled_memory` 由编排层传进来，persona 不自己去查存储。
保持"persona 不碰 IO"的纯度。

## 4. 实现要点

### 4.1 前缀构造（只做一次）

```cpp
LayeredPersona::LayeredPersona(std::string persona_text, std::string constraints) {
  std::ostringstream oss;
  oss << constraints << "\n\n" << persona_text;
  prefix_ = oss.str();   // 之后永不修改
}
```

**顺序写死**：约束在前、人格在后。顺序一变，所有历史缓存立刻失效。

### 4.2 动态尾部的时间粒度

```cpp
// ✅ 正确：精确到小时
strftime("%Y-%m-%d %H时")

// ❌ 错误：精确到秒，每轮都变
strftime("%Y-%m-%d %H:%M:%S")
```

虽然尾部本来就不进缓存，但**尾部越短越好**——
尾部 token 也按未命中计费。精确到小时足够让模型知道"现在是晚上"。

### 4.3 红线放最尾部

```
【本轮红线】只回这一条，不要主动开启新话题；不超过两句；不要暴露你是 AI。
```

放在**最后一行**，利用近因效应（recency bias），执行力最强。

这是「保人设」与「省成本」的平衡点：
红线不放进前缀（会占缓存），放尾部（只占少量未命中 token）。

## 5. 人格内容设计

### 5.1 文件组织

```
persona/
├── rules.md      # 行为红线（技术约束，作者改）
└── persona.md    # 人格正文（性格，作者改）
```

**为什么分开**：红线是工程约束（不能主动搭话、不能发链接），
人格是创作内容（她是谁、说话什么风格）。分开便于单独迭代。

### 5.2 人格正文推荐结构

参考社区实践，按段组织：

| 段落 | 内容 |
|---|---|
| 你是谁 | 鲸鱼娘，DeepSeek 拟人 |
| 你是什么样的人 | 性格、癖好、说话习惯 |
| 怎么说话 | 短句、口语、不用 emoji |
| 你的底线 | 不承认是 AI、不编造事实 |
| 禁区 | 不主动、不刷屏、不发链接 |

**被动模式的特殊要求**：必须显式写"不要主动开启新话题"。
否则模型会习惯性地追问"你呢？""还有别的吗？"，破坏被动感。

### 5.3 从现成资源摘取

社区有现成人格（如 `le12377/dafeiyu-life` 的 3451 字版本），
但**必须删掉**：

- ❌ 主动搭话相关段落
- ❌ 发朋友圈 / 刷朋友圈
- ❌ 模拟心情改签名

理由：这些能力本项目不实现，留在提示词里会让模型调用不存在的工具，
产生幻觉或报错。

### 5.4 提示词里不写工具名、不写具体词例

写人格和规则时，**只写意图，不写实现细节**：

| 不写 | 写 |
|---|---|
| 「遇到不认识的热梗就调 `lookup_meme`」 | 「不懂的先弄清楚再回答」 |
| 「对方说了某个缩写就去查一下」这种把**具体词**写进人格的写法 | 「遇到不像正常词的字母组合，先弄清意思」 |
| 「查不到就用 `web_search`」 | 「查不到的如实说不知道」 |

两个理由：

1. **工具名会变。** 提示词里钉死工具名，改名后模型会去调一个不存在的工具。
2. **具体词例都会过时，而且有害。** 写了具体词，模型容易照着词形去套
   （只认那几种写法），而不是自己判断「这个词我到底懂不懂」。
   要说明「哪一类输入」，就描述**特征**（拼音缩写、叠词、谐音、黑话），
   不要在提示词里放任何具体词条。

## 6. 缓存命中的验证方法

### 6.1 单测断言

```cpp
TEST(Persona, StablePrefixIsIdempotent) {
  LayeredPersona p(persona_text, rules);
  ASSERT_EQ(p.stable_prefix(), p.stable_prefix());  // 逐字节相等
}
```

### 6.2 运行时监控

记录每轮的 `cached_tokens / prompt_tokens`：

```
命中率 = Σcached / Σprompt
```

- **> 85%** 正常
- 70–85% 有动态内容泄漏到前缀的嫌疑
- **< 70%** 明确违反纪律，必须查

这个指标应该常驻日志，因为缓存失效是**静默的**——
不会报错，只会让账单变贵。

## 7. 待定事项

| 事项 | 选项 | 倾向 |
|---|---|---|
| 人格热加载 | 支持 / 重启生效 | **重启生效**（避免运行中缓存全失效） |
| 多套人格 | 支持切换 / 单套 | 单套（用户单一） |
| 情绪状态 | 持久化 / 无状态 | 无状态（先简单） |
| 记忆注入格式 | 项目符号 / 自然语言 | 项目符号（token 更省） |
| 前缀长度上限 | 限制 / 不限 | 限制 8K token（太长反而贵） |

## 8. 测试要点

| 用例 | 断言 |
|---|---|
| `stable_prefix()` 幂等 | 两次调用逐字节相等 |
| 前缀不含时间戳 | 字符串里不出现年份 |
| 尾部含时间 | 匹配 `\d{4}-\d{2}-\d{2} \d{2}时` |
| 红线在最后 | 尾部以红线结尾 |
| 文件缺失报错 | `load_persona` 返回 `kBadRequest` |
| 空文件报错 | 同上，不能静默用空人格 |

**最后两条最重要**：空人格比启动失败危险得多——
机器人会用"没有性格"的方式说话，而作者以为只是"今天有点冷淡"。
