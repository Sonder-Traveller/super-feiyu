# ADR-005：阻塞 IO + 固定线程池，不用异步

**状态**：已定

---

## 决策

用**阻塞式 HTTP 客户端 + 固定大小线程池**（2 个工作线程），
不使用 Asio / epoll / 协程。

## 背景

典型异步理由：高并发、海量连接。本项目完全不符合：

| 指标 | 本项目 | 异步收益 |
|---|---|---|
| 并发消息 | 个位数 | 无 |
| 上游调用 | 每条消息 1–3 次 | 无 |
| QPS | < 1 | 无 |

## 收益

| 项 | 说明 |
|---|---|
| 代码简单 | 线性流程，无回调地狱 |
| 调试容易 | 调用栈完整，断点直观 |
| 依赖少 | libcurl 同步模式即可 |
| 正确性 | 无回调生命周期问题 |

## 代价

| 代价 | 缓解 |
|---|---|
| 线程阻塞 | 2 个 worker 够用（消息本来就串行） |
| 无法处理突发 | 有界队列 + 背压丢弃 |
| 一个慢请求占住 worker | 全部调用有超时（8 s） |

## 线程数论证

最坏情况：两条消息同时处理，各调一次 LLM（8 s）。
2 个 worker 正好，再多也是空转。

定时线程独立（清扫预算/去重/指标），不与 worker 竞争。
通道线程每通道 1 个（阻塞 poll）。

**总计 5 + N 个线程**（N = 通道数）。2C1G 上调度开销可忽略。

## 什么情况下应该重新考虑

- 并发消息 > 50（不会发生）
- 需要同时对接 10+ 通道（不会发生）
- 单请求延迟要求 < 100 ms（LLM 本来就慢）
